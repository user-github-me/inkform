# Contributing to Inkform

Contributions that improve geometry, source provenance, document correctness,
cross-platform support, or the learning workflow are welcome. For a substantial
change, open an issue describing the problem and a small reproducible example.

## Development setup

Use Python 3.11 or newer. From a checkout:

```sh
uv venv --python 3.12
uv pip install -e '.[dev]'
.venv/bin/pytest -q
npm test
```

Node.js 20+ runs the npm launcher tests; no npm dependencies are needed.
`npm run test:package` additionally installs and exercises the packed engine;
its initial dependency setup requires network access. Without `uv`, create a standard virtual environment and install with
`python -m pip install -e '.[dev]'`. On Windows, activate the environment or use
the executables under `.venv\Scripts`.

To check a public example:

```sh
.venv/bin/inkform render examples/calibration.json \
  --profile examples/synthetic-profile.json --output build/demo.pdf
.venv/bin/inkform check build/demo.pdf --manifest build/demo.build.json
```

## Keep contributions free of personal handwriting

Public issues, pull requests, commits, and packages must not contain someone's
handwriting photographs, extracted masks, writer profiles, review ledgers,
transcripts, or generated personal documents. A vector trace can reveal the
same personal forms as a photograph. Removing a name does not turn those forms
into a synthetic fixture.

Use deliberately invented coordinates or simple drawn shapes for examples and
tests. The bundled `examples/synthetic-profile.json` is generated by
`scripts/make_synthetic_profile.py`; it contains no personal source evidence.
Keep real experiments in Inkform's private data directory, outside the checkout.
Check filenames, logs, JSON metadata, and images before sharing: source paths
and review actors can also contain personal information.

## Pull requests

Explain the observed problem, the resulting behavior, and the relevant checks.
Add a regression test when it demonstrates a meaningful failure. Tests must run
without personal data, paid accounts, credentials, or network services. For
geometry changes, use synthetic fixtures to check topology, finite bounds,
determinism, and preservation of detached marks; include a synthetic visual
comparison when it helps review.

Keep labels, observations, fitted geometry, and rendering instances distinct.
New geometry must retain its evidence and remain proposed until reviewed.
Do not bypass missing-glyph checks, silently replace a personal form with a
font, or claim recovered pressure/timing from a photograph. Document new
capabilities and limits in the same change.

Before submitting, run the relevant tests and `git diff --check`, then inspect
the complete diff for generated private data. Contributions must be yours to
share under the project's applicable license; identify any third-party code or
assets and their licenses.

For release archives, run `scripts/check_public_release.py` with the npm,
Python, or standalone-skill archive paths. It inspects the archives without
extracting them, checks synthetic profile provenance, and rejects private or
unexpected assets. The introduction site under `docs/` uses explicitly
documented synthetic assets only.
