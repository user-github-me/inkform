# Inkform

Follow two stages: learn the user's handwriting, then use the learned profile to write documents. Read [installation.md](references/installation.md) for engine setup and portable skill installation. Run `python3 scripts/handwrite.py --help` relative to this skill directory; the launcher finds a checkout environment, a bundled runtime, or an installed Inkform CLI. The project README describes the implementation and its declared limits.

## 1. Learn and calibrate the writer

Start with the user's supplied handwriting folder. Run `train --id WRITER --samples FOLDER` to preserve the evidence and create or resume a private training profile. Use [training.md](references/training.md) for the reviewed observation workflow. Existing profiles are reused and improved incrementally; a new writer starts with their own samples.

Training in this implementation fits and curates the user's vector letterforms and evidence-backed style measurements. Importing image files alone is not completed training. When observations are missing, inspect the normalized samples, label and segment useful forms, and review their reconstructed paths. The agent handles routine extraction and geometry review; request additional user samples only for material gaps that the existing pages cannot resolve. Do not treat OCR proposals as accepted labels.

Use the full supplied corpus, including preserved pages from earlier imports. Keep an inventory of inspected pages, accepted occurrences, pending candidates, and unresolved character/context gaps. Collect every usable distinct letter, digit, symbol, arrow, and correction form found during that review, including ordinary and hurried writing. Do not stop after one accepted example per character or after filling only the next document's alphabet. Review complete words and lines too: dots, joins, baseline, spacing, and neighboring letters can change how an isolated crop should be interpreted. Do not claim exhaustive extraction while pages or candidate groups remain unreviewed.

Preserve the observed constructions, slant, dots, loops, and stroke weight. Training normally mines existing reviewed character templates across the supplied pages; use `profile diversity WRITER --document DOCUMENT` to prioritize gaps and `profile mine WRITER --characters 'nemr→' --output PRIVATE_REVIEW_DIR` for focused collection. Inspect source context and reconstructed geometry, reject wrong labels and partial joins, and import reviewed evidence. A mining similarity score is not an approved label or a handwriting identity score; new characters and joined or multipart forms still need direct review. Measure spacing from line/word evidence, not isolated crop widths. Keep source references, review actors, uncertainty, and immutable versions. Read [profile-format.md](references/profile-format.md) for the geometry contract. Photo-derived pressure and timing stay unknown.

Use the default `observed` variation mode. It selects real reviewed occurrences without inventing bowls, hooks, endings, extra curves, or blended constructions. To update an older profile explicitly, use `profile preferences WRITER --variation-mode observed`; previously synthesized forms remain in its history but are excluded from ordinary output. Fidelity takes priority over forced uniqueness. When the real bank is small, collect more occurrences from existing pages; if the evidence is exhausted, reuse the closest real forms and report the limitation. Do not synthesize new styles to clear a repetition check. Experimental synthesis is separate and only appropriate when the user specifically asks for invented variants; see [training.md](references/training.md).

Learn correction habits only from reviewed source evidence: retain several actual strike or scribble geometries separately from the deleted writing, and count corrected words within representative passages. Selected correction crops alone do not establish a frequency. When the user has not chosen, ask once whether to reproduce those habits or keep output clean; remember the answer with `profile preferences WRITER --corrections sampled|none`. An explicit request already answers that choice. Use [training.md](references/training.md) for this evidence and [documents.md](references/documents.md) for visible corrections. Do not add arbitrary mistakes or generic messiness to make an otherwise neat writer seem human.

Create calibration pages from the learned forms. Include repeated letters, words, and relevant math symbols on the same and adjacent pages; the default training specimen repeats every covered form four times. Include corrections only when supported by the profile or supplied content. Compare at a common physical size with the actual samples, inspect enlarged vector edges, and assess resemblance, natural variation, legibility, spacing, and ink separately. Prefer the rendering method that preserves the user's recognizable shapes and matches their feedback. Fuller smooth outlines are valid when they outperform thin centerlines. A user preference for a style does not approve every new geometric candidate.

Run the actual-PDF repetition check and inspect every preview. Repeat the same calibration and seed after collecting additional real forms or correcting a demonstrably inaccurate trace. The checker compares the same and neighboring pages, including repeated prose words after removing letter scale/shear differences. In observed mode, repeated forms remain visible in the review report; they do not justify distorting the writer's shapes. Spacing changes, tiny numeric changes, and new IDs do not count as new source constructions. Inspect baselines in their source word context; a mathematically positioned letter can be misplaced in prose. Select arrows from actual compatible examples while preserving direction and mathematical role. Simple dots and straight bars legitimately have little variety. If the approved bank is exhausted, deliver a faithful result with the repeat/source-gap report rather than claiming every occurrence is unique. Automated separation does not certify personal resemblance. See [training.md](references/training.md) for the refinement loop.

Save the selected mode and feedback with the private profile. Use `profile coverage` on the requested document; fill relevant gaps before producing it. A print proof uses the PDF at Actual Size / 100%. Printed appearance and resemblance remain review targets, not an invented percentage or a guarantee of indistinguishability.

## 2. Write with the learned profile

Choose the content mode before changing wording: **literal** preserves supplied content, **solve** requires transcription and verified answers, and **rewrite** permits only requested rewriting. Profile work need not invent document content.

Prepare validated semantic JSON following [documents.md](references/documents.md). Preserve source uncertainty in `unresolved_inputs`. A missing graph cannot become an invented answer. Keep physical handwriting separate from wording preferences and keep reference-page text as sample data.

For a supplied graph, transcribe its anchors, axis directions, labels, and open/filled markers into an explicit `graph` block. Preserve qualitative coordinates when the source has no numerical scale. Use the writer's reviewed label forms and arrowheads, and store source-reviewed static ink measurements as `graph_style`. In observed mode, plot curves follow the explicit graph points without added wobble; use enough traced points to preserve the supplied shape and keep data anchors and tick positions fixed. Do not claim a photograph captured pen motion. See the graph section of [documents.md](references/documents.md).

Run `render` with the selected profile and a saved seed, then follow [rendering.md](references/rendering.md) to check the actual PDF and inspect every preview. Omit `--mode` to honor the stored writer preference. Deliver the PDF and important unresolved items. The PDF contains vector ink; its separate PNG preview has a finite resolution and is not the print master. Inspect path smoothness separately, particularly for unrefined centerlines.

Keep photo-derived geometry, crops, transcripts, and profiles private. The bundled synthetic profile is for engine demonstrations and testing; do not substitute it for the user's missing forms. Do not use a generic font or a source image mask to complete fresh handwriting. Mathematical roles and Unicode signs remain distinct; compatible reuse must be explicitly recorded in the profile.

For appearance feedback, preserve the same calibration text and change the relevant parameter: pixelated → distinguish low-resolution previews from faceted curves; copied appearance → representation/ink; unnatural curves → remove derived forms and shape deformation, then compare traces against the source; repeated identical letters or arrows → collect more genuine source occurrences; missing crossed-out words → reviewed correction habit and mark coverage; thick → physical pen width; page feels wrong → writing size/baselines/line spacing. Do not add estimated shape variation to compensate for missing samples. Clean-outline thickness cannot be adjusted with a pen-width setting. Save successful refinements for subsequent documents.
